# Internationalisation

How user-visible text is stored, translated, selected and rendered. Every
string a user can read in the settings window, the tray menu, Mission
Control, the space indicator and the hotkey labels comes from one table per
language, compiled into the binary.

*Last verified: 2026-09-06, against b18bf56.*

---

## 1. Mechanism

`crates/winspaces-common/locales/<tag>.json` holds one flat JSON object per
language: `"key": "text"`. `en.json` is the **reference** — its key set is the
schema. `crates/winspaces-common/build.rs` reads every file at build time and
generates `$OUT_DIR/i18n_gen.rs`, which `src/i18n.rs` includes:

- `enum Lang { En, Es, … }` — one variant per locale file, `En` always 0.
- `enum Msg` — one variant per simple key, PascalCased from the key
  (`settings.system.show_all.title` → `SettingsSystemShowAllTitle`).
- `enum PluralMsg` — one variant per plural group (§3).
- `static TABLE_<LANG>: [&str; MSG_COUNT]` and `PLURAL_<LANG>` per language.

Runtime API (`winspaces_common::i18n`, re-exported at the crate root):

| Call | Returns | Use |
| :--- | :--- | :--- |
| `t(Msg)` | `&'static str` | a message without arguments; never allocates |
| `tr!(Msg::X, n = i + 1, path = p)` | `String` | `{name}` substitution (`tf` underneath) |
| `tn(PluralMsg, n, &[("n", &n)])` | `String` | plural form picked by CLDR category |
| `t_in / tf_in / tn_in(lang, …)` | same | pure variants for tests |
| `i18n::current()` / `set_current(Lang)` | | the process-wide language (`AtomicU8`) |
| `Lang::resolve(&config.language)` | `Lang` | `"system"` → Windows display language, a tag → that language |

Why this and not a crate: the dependency policy (`windows-sys` + serde only),
the single-binary rule, `&'static str` returns, and the build-time checks. The
only addition to the build is `serde_json` as a `[build-dependencies]` entry —
already in the lockfile. Cost: +22 KB on the release exe for one extra
language (629 KB → 652 KB).

## 2. Build-time checks

`cargo build` fails on: unknown key in a translation, placeholder set that
differs from English, unbalanced braces, a plural group without `.other`, two
keys mapping to one variant name, a non-string value, missing `en.json`. A
translation that is merely **missing** a key produces a `cargo:warning` and
the English text is compiled into that slot, so a language can land
incrementally and runtime never sees an empty string.

## 3. File format

- Keys: `surface.area.item[.part]`, lowercase, `_` inside a segment. Surfaces
  in use: `settings`, `banner`, `reason`, `dialog`, `theme`, `lang`, `tray`,
  `mc`, `indicator`, `key`.
- Placeholders: `{name}`; `{{` / `}}` are literal braces. An unknown
  placeholder at a call site is left in the output verbatim (and trips a
  `debug_assert!`), never dropped silently.
- Plurals: a key whose last segment is a CLDR category (`zero one two few
  many other`) belongs to a plural group named by the rest of the key.
  `other` is mandatory in `en.json`; every other form is optional per
  language. `plural_category(Lang, n)` in `i18n.rs` holds the rules and is an
  exhaustive `match` — a new locale file does not compile until its rule is
  written.
- `reason.*` strings are sentence fragments **without** a trailing period:
  `banner.autosave.message` (`"{reason}. WinSpaces daemon reloaded…"`) supplies
  the punctuation.
- `lang.name` is the language's own name for itself (`"Español"`) and is the
  combo label; it is deliberately never translated into another language.

## 4. Selecting the language

`Config.language` (`settings.json`) is `"system"` by default (follow the
Windows display language via `GetUserDefaultUILanguage`) or a tag with a
locale file (`"en"`, `"es"`). `normalize()` lower-cases it, maps `"es-ES"` to
`"es"` and anything unknown back to `"system"`.

- **Daemon**: `main.rs` sets the language right after loading config, before
  any UI exists, and `handlers::ipc::apply_config` sets it again on every
  reload — both the settings-window IPC and the tray "Reload Configuration"
  go through that one function. The tray menu is rebuilt per right-click,
  Mission Control formats in `WM_PAINT`, and the indicator keys its text
  cache by the label, so none of them need a nudge.
- **Settings window**: `SettingsState::new` sets it after loading config; the
  System-page *Language* combo writes `config.language`, calls
  `set_current`, retitles the window (`SetWindowTextW`), autosaves (which
  posts the reload to the daemon) and relayouts — the whole window switches
  in one frame because every string is read at layout/paint time. An
  imported configuration applies its own language the same way. *Reset to
  Defaults* keeps the current language.
- The settings single-instance check finds the running window **by class
  only** (`FindWindowW(class, null)`): the title is localized.

## 5. Hotkey labels

`hotkey_to_string` renders in the current language through `Msg::Key*`:
modifiers (`Ctrl`, `Alt`, `Shift`/`Mayús`, `Win`), `Unassigned` and the named
keys (Tab, Esc, Space, Enter, Backspace, Delete/`Supr`, Home/`Inicio`,
End/`Fin`, PageUp/`Re Pág`, PageDown/`Av Pág`, arrows). Letters, digits,
F-keys and punctuation are untranslated. Order (Ctrl, Alt, Shift, Win) and
the `+` joiner are fixed. `GetKeyNameTextW` was rejected: it names keys after
the keyboard *layout* and the OS language, not the app language, and is not
deterministic under test. The tray menu's shortcut column comes from the
configured bindings (`config.switch_spaces[i]`, `config.mission_control`);
`Win+Tab` is composed from `key.win` + `key.tab` because it is the
low-level-hook intercept, not a registered hotkey.

## 6. Layout under longer text

- Settings cards: the description wraps to at most two lines
  (`DT_WORDBREAK | DT_EDITCONTROL | DT_END_ELLIPSIS`); `pages::layout`
  measures it with `measure_text_wrapped` at the same width the paint pass
  draws at (`CARD_TEXT_LEFT`, `CARD_TEXT_GAP`, `trailing_left`) and grows the
  card from its 68 dip minimum, re-centring the trailing controls. Headers,
  nav labels and button labels stay single-line with ellipsis; buttons,
  combos and hotkey fields size to their text.
- Banner: the title is capped at half the banner width and ellipsizes, so a
  long translated title cannot push the message off-screen.
- Tray flyout: measured, clamped to `MAX_W = 520` dip.
- Mission Control: the "New Space" tile is sized from the measured label
  (`MissionControl.plus_label_w`, refreshed with the fonts on every show);
  the empty-state line ellipsizes.

## 7. Pseudo-locale

Debug builds only: `WINSPACES_PSEUDOLOC=1` in the environment swaps every
lookup for a bracketed, accented, 40 % longer transform of English
(`[Ẃéĺćómé {n}~~~]`), placeholders intact. Any text on screen **without**
brackets is a literal that bypassed the table; any clipped card is a layout
that assumed English widths. The table is `#[cfg(debug_assertions)]` and
costs the release binary nothing.

## 8. Adding a language

1. Copy `locales/en.json` to `locales/<tag>.json` (`tag` = lowercase ISO 639-1,
   e.g. `de`). Translate the values only; keep every `{placeholder}` and
   `{{`/`}}` verbatim.
2. Set `lang.name` to the language's self-name.
3. Add or drop plural suffix keys per the language's CLDR rules (`other`
   always).
4. `cargo build`: `Lang::<Tag>` now exists and the build fails at the
   exhaustive matches in `i18n.rs` (`plural_category`, `Lang::from_langid`)
   until the language's plural rule and primary `LANGID` are added.
5. `cargo test -p winspaces-common`; check `every_lang_has_a_self_name`.
6. Debug build with `WINSPACES_PSEUDOLOC=1` is the width check; the real
   language is the wording check.
7. `installer/winspaces.iss`: add the matching `[Languages]` line
   (`compiler:Languages\<Name>.isl`) and the `[CustomMessages]` block.

## 9. Deliberately not translated

Log lines (`log_*!`), the `--elevation-status` console output, window class
names and the IPC message-window title, registry keys, the scheduled-task
name `WinSpaces Daemon (Elevated)`, JSON keys, the tray tooltip brand name,
window titles of other apps. RTL and CJK are out of scope: the fonts are
Segoe UI Variable with `DEFAULT_CHARSET` font linking only, and the layouts
are hand-computed left-to-right.
